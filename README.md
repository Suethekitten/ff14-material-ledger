# FF14 材料台账

记录材料分散在各个角色 / 仓库里的数量，之后按名字、角色、位置广域搜索。

## 怎么跑

双击 `启动.bat`。浏览器会自动打开 `http://127.0.0.1:8765/`。

命令行方式：

```
python app.py                 # 启动服务
python app.py --selftest      # 只跑一遍逻辑，不开浏览器（排查用）
python app.py --no-browser    # 启动服务但不自动开浏览器
python app.py --port 9000     # 换端口
python app.py --clear-demo    # 删除示例数据
```

## 首次启动会做什么

1. 建目录 `data\`、建表 `data\stock.db`
2. 没有 `data\items.json` 时，从国服数据源下载物品表并裁剪（约 19MB，只此一次）

   来源：`https://cdn.jsdelivr.net/gh/thewakingsands/ff14-datamining-cn@master/Item.csv`

   下载失败不影响使用，只是物品名没有联想（仍可手动输入名称记账）。
3. 灌入示例数据（账号名以「示例」开头），界面顶部会提示，可一键清除

## 界面（v0.10）

两栏工作台：**左栏查库存，右栏常驻「记一笔」**；审计、对账、成本、名字映射、快照、部队、数据急救、快捷键都收在右上角「管理」抽屉里。

## 部队（v0.9）

部队柜是**共享**仓库，多个角色各记一份会让合计翻倍。

- 建部队 → 角色加入 → 录库存时位置选「部队柜」
- 同一材料被多人记过时，面板提示**冲突**
- 「归并部队柜」：数量由你确认（不自动求和），旧行作废并写流水
- 解散部队：先打快照，再二选一
  - 按解散处理：库存作废并留给水（FF14 里部队解散后箱里东西会消失，不能挂回角色）
  - 我已经把东西搬空了：直接解散

## 买入成本（v0.10）

录入时填「买入单价」才记成本，且**只有数量增加才记**（清点、覆盖、减少都不算采购）。

- 材料头显示 `均 16.7 gil · 2 批 · 估值 110,123`，点开展开批次明细
- 均价加权：Σ(数量×单价) ÷ Σ数量
- 删掉某条批次，均价立刻重算
- 没有批次的旧库存，点「设成本 ⊕」填基线单价

## 位置与雇员

- **角色仓库**：背包、鞍囊、部队柜、房屋等
- **雇员**：雇员1、雇员2…，数量按数据里实际用到的最大序号自动生成
- 需要更多时点「＋ 新增雇员N」，按角色分别记住
- 选中雇员N 时右侧出现「删」，可清空该位置全部库存（两次确认 + 自动快照）

## 数据急救

「管理 → 数据急救」显示真实数据库路径、大小、角色/库存数。

- 立即备份：手动打快照
- 选择 .db → 导入并覆盖：整份换回（原库自动备份为 `stock.bak-时间戳.db`）
- 程序起不来时用 `恢复数据.bat`：把 `.db` 拖上去

## 未确认库存（v0.11）

删掉一个雇员栏位时，**里面的库存不会被删除**，而是转入「未确认库存」。

为什么：库存是实物，不能因为栏位没了就消失。典型场景是账号里已经没有雇员3，
但账本里还有记在「雇员3」下的货。

处理方式（管理 → 未确认库存）：

- **转移**：选角色 + 位置，数量并入目标格（目标格已有同材料则**相加**）
- **丢弃**：真正删除，先自动打快照，并写流水留痕

未确认的库存**不计入**主列表和总合计，顶部会单独显示：

```
角色 3 个 · 库存 19 条 · 合计 11,944 件 · 未确认 2 行 260 件
```

## 怎么把货物搬位置（v0.11.2）

搬货只改位置，**总数不变**。三种方式：

| 方式 | 操作 | 适用 |
|---|---|---|
| 一次搬完 | 行内「改」→ 同时改数量和位置 → 保存 | 日常推荐，一个事务完成 |
| 分两步 | 旧位置「取」→ 新位置「记一笔」 | 想分开记录时 |
| 整格搬 | 位置框旁「删」→ 转入未确认 → 再转移 | 整个雇员栏位没了 |

底层接口 `POST /api/stock/move`，保证“减源 + 加目标”同时成功，不会出现旧行没了、新行没进来的情况。
流水会写两条（搬出 / 搬入），所以审计里该材料的**净变化是 0**。

## 升级前先导出 CSV

跨版本升级（如 0.7.x → 0.10.x）前，先双击 `紧急拆封CSV.bat` 并拖入 `data\stock.db`，
生成 `emergency-stock-时间戳\`，其中 **`01-库存（可直接导入）.csv`** 可在新版本里用

## 打包成 EXE

双击 **`build_exe.bat`**（首次会自动装 `pyinstaller` 和 `pywebview`，约 1-3 分钟）：

```
dist\ff14-stock\ff14-stock.exe     ← 双击运行，对方不需要 Python
```

要点：

- **发的是整个 `dist\ff14-stock` 文件夹**，不是单独一个 exe
- 包里已经带 `static\` 和 `data\items.json`（在 `_internal` 里）
- 数据（`stock.db`、快照、日志）会生成在 **exe 同级的 `data\`** 里；如果 exe 放在不可写目录，会自动改用 `%LOCALAPPDATA%\ff14-stock`
- 当前保留控制台窗口（能看到启动信息和报错）；稳定后可把 `build_exe.bat` 里的 `--console` 改成 `--windowed`
- 想打成单文件：把 `--onedir` 换成 `--onefile`，但启动会慢 2-4 秒、杀软误报概率更高

## 内嵌窗口（可选）

默认走浏览器。想让它像桌面软件一样开独立窗口：

1. 双击 **`安装内嵌窗口.bat`**（执行 `pip install pywebview`）
2. 重新运行 `启动.bat`

启动时会打印 `窗口：内嵌窗口（关掉窗口即退出）`，之后就是一个没有地址栏的独立窗口。

- 想强制用浏览器：`python app.py --browser`
- 两者都不想要（只起服务）：`python app.py --no-browser`
- 内嵌窗口依赖 Windows 的 WebView2 运行时，Win11 自带，Win10 多数已装；缺失时会自动回退浏览器

## 图标说明

那份国服 `Item.csv` **没有 Icon 列**（实测 51198 条全部缺图标 ID）。所以图标走「按需取」：

- 页面上出现某个材料时，才向 XIVAPI 批量请求这些物品的图标
- 一批请求复用一个长连接，避免每条都重新 TLS 握手（国服网络下握手就要 1~2 秒）
- 拿到的地址存进 `data\icon_map.json`，之后本地就有了
- 失败的物品进入 120 秒冷却队列，之后可自动重试；取不到就留空，不显示破图

启动时控制台会打印一行自检：

```
[自检] 物品名解析正常：铁锭 → item_id 5057
```

如果打的是警告，说明物品表里的名称列认错了，打开 `/api/diag` 看 `items_sample`。

## 记错了怎么改

结果表每行右侧有「改」和「删」：

- **改**：把这一行的角色/位置/数量填回下方录入表单，改完点保存即覆盖
- **删**：点一次变「确认删」，3 秒内再点一次才真正删除（防误触）

每次增删改都会写流水，页面底部「最近操作」能看到时间、动作、角色、结余。

## 名字没被物品库收录怎么办

国服物品表有 5 万多条，但仍有少量物品没有可用的中文名。表现为结果里显示「（未收录）」、`#—`，并且没有图标。

处理方式：点那行的「**绑定**」，然后三选一：

- **搜中文名片段**（例如 `黑铁`）从本地物品库挑
- **搜英文名**（例如 `Iron Ingot`），会去 XIVAPI 查，结果里带匹配度
- **直接填物品 ID**（例如 5057），点「按 ID 查」会带回英文名确认

如果游戏刚更新、转储还没收录这件物品，可以点弹窗右下角的「**这批先按原名临时记录**」——先记下来，等数据更新后在「未收录的材料」里补绑。

## 备注名（名字映射）

一个物品可以挂多个备注名，作用有两个：

- **输入映射**：打 `铁锭` 自动解析成 `黑铁锭`
- **搜索命中**：搜 `铁锭` 能找到 `黑铁锭` 的库存，结果标题会标「备注：铁锭」

管理入口在页面下方「名字映射」：可以查看全部映射、删除、新增（物品填名字或 `#ID`）。

记录里**始终存标准名**，备注名只用于输入和搜索，不会污染数据。

## 「组」与格数

仓库一格最多 999 件，游戏里习惯叫「一组」。

- 显示：合计显示为 `1组524/1523 · 2格`（组+余数 / 总量 · 占用格数）；不足一组只显示数字
- 行内：显示 `1组524`（或 `524`）
- 输入：可以填 `1523`，也可以填 `1组524`、`1组`，输入框下方会实时显示换算结果和占格数
- 存储：**只存总数量**，组与格都是显示层换算，不会出现两套数字
- 不可堆叠物品（家具、装备等 `StackSize = 1`）：材料名旁标「单体」，数量只显示件数，输入「N组」会被拒绝

堆叠上限来自物品表（重建 `items.json` 时会一并写入 `StackSize` 字段），不是写死 999。

## 导入库存 CSV

「＋ 导入库存 CSV」选文件后**先预览、不写库**，弹窗显示：

```
共 18 行 · 新增 12 条 · 覆盖 5 条 · 跳过 1 条
将新建角色：某某@豆豆柴
跳过明细：第 7 行 XXX：物品库未收录，先绑定名称再来
```

然后选择：

| 按钮 | 行为 |
|---|---|
| 覆盖导入 | 同一格（角色+位置+材料+HQ）已有数据时，用 CSV 数量替换 |
| 追加导入 | 已有数据 + CSV 数量 |
| 取消 | 什么都不写 |

规则：

- 需要带表头的 CSV（`material,character,location,hq,qty`，`world`/`account` 可选）
- **库里没有的角色会自动创建**（用 CSV 里的角色名/服务器/账号）
- **物品名认不出的行会被跳过**，导入结果里逐条列出，之后自己补录
- 导入前自动打一份「导入前自动存档」快照，导错了可以恢复

## 撤销上一步

「最近操作」工具栏的「撤销上一步」（点两次确认）：

- 只会撤销**最近一条**库存操作，不是随便挑历史
- 反向修改库存：新增→删掉该格、取出→加回去、覆盖→回到操作前的数量、删除→重建该行
- 原流水会被标为异常并注明「已被撤销」，同时写一条「撤销」流水，账目仍可追溯
- 撤销本身不能再撤销，要回退更早状态请用快照

## 对账

「对账」面板的「检查」会逐格比较：

```
现在 1组524/1523   流水 1组524/1523   差 0    阿辉@豆豆柴 / 背包
现在 640            流水 739            差 -99  老陈@豆豆柴 / 雇员1
```

- 口径：当前数量 vs 该格所有流水 delta 之和（含被标为异常的流水，因为它们确实改过库存）
- 全部对得上会显示「没有差异」
- 注意：早期流水没有「品质」字段，HQ 行可能出现误报

## 快捷键（可录制）

页面底部「快捷键」：

- 点「录制」，直接按组合键即可（必须带 Ctrl 或 Alt，单个字母会被拒绝）
- `Esc` 取消录制；「恢复默认」还原成 `Ctrl+Enter` 保存、`Ctrl+K` 聚焦搜索
- 设置存在浏览器本地，换浏览器不会跟随

## 错误日志

后端异常会写进 `data\error.log`（带时间、接口名、堆栈），超过 200KB 自动裁掉前半段。程序出问题时先看这个文件。

## 批量粘贴录入

页面里「＋ 批量粘贴录入」，一行一条：

```
黑铁锭 1组524
亚麻 300 雇员1
黄铜锭 60 hq
# 这一行是注释，会跳过
```

- 格式：`材料名 数量 [位置] [hq]`
- 位置省略时用左边选中的默认位置
- 数量支持 `524` 或 `1组524`
- **同名材料 + 同一角色 + 同一位置 + 同一品质是「覆盖」不是「累加」**：写两行只保留最后一行。导错了到「快照」里恢复
- 名称必须能在物品库或备注名里对上，否则该行失败并提示
- 最多一次 500 行
- 导入完成会列出行结果：成功 / 未变 / 失败

## 导出库存 CSV

搜索结果面板右上角「导出库存 CSV」，字段：

```
material,item_id,character,world,account,location,hq,qty,groups,slots,updated_at
```

## 空操作不再记录

数量与原来完全一致时，保存只提示「未产生改动」，不写流水、不打快照，避免流水里堆满 `覆盖 +0`。

## 快照（可回滚）

**每执行一次「存 / 取 / 改 / 删 / 改备注名」成功后，自动给数据库存一份快照**，自动快照只保留最近 30 个。

| 操作 | 说明 |
|---|---|
| 立即打快照 | 手动存一份，可填备注（如「建仓完成」），**手动快照不会被自动清理** |
| 查看 | 只读打开这份快照，看那一刻的库存长什么样 |
| 恢复 | 点两次确认，提示会丢失之后多少条操作。恢复前会先把当前状态存成「恢复前」快照，所以恢复本身也能反悔 |
| 下载 | 把某份快照另存为 .db 文件，便于拷贝备份 |
| 删 | 点两次确认，只删这一份快照 |
| 清理旧快照 | 删掉早期没有操作摘要的自动快照（列表里默认不显示它们） |

自动快照的备注会写成操作摘要，例如：

```
存入 黑铁锭 1组524/1523 → 阿辉@豆豆柴 / 背包
取出 黑铁锭 999 → 阿辉@豆豆柴 / 背包（剩 524）
```

快照文件在 `data\snapshots\`，用 SQLite 的 backup 接口生成（WAL 模式下直接拷文件可能拿到半截数据）。

> 注意：因为每次写操作都会存快照，30 个自动快照大约等于「最近 30 步可回滚」。想保住某个关键状态，请用「立即打快照」存成手动快照。

## 审计

页面下方「审计」面板按材料汇总一段时间内的进出：

- **时间范围**：今天 / 7 天 / 30 天 / 全部，也可以直接选起止日期（按本地时区切分）
- **四列分开**：新增（store）、取出（take）、调整（set 覆盖）、删除（clear），另有「净变化」
  - 之所以不合并成一个净数：覆盖操作可能加也可能减，混在一起会对不上账
- **涉及角色**：这一栏列出这段时间动过该材料的角色
- **已核对**：底部流水每条前面有勾选框，勾上会永久保存并记录核对时间；顶部工具栏可「全勾当前 / 全不勾当前」
- **标记异常**：每条流水右侧的「异常」可把这条标成记录错误，并填一句原因（可空）。异常行会变灰划线，**自动从审计统计中排除**；点「恢复」可撤销标记，原因保留
- **核对状态筛选**：全部 / 只看已核对 / 只看未核对 / 只看异常
- **按物品 ID 合并**：同 ID 的不同叫法（例如历史记录里的「铁锭」和现行的「黑铁锭」）会合并成一行统计
- **导出**：`复制汇总`（贴到群里或自己存）和 `导出 CSV`（带 BOM，Excel 直接打开不乱码）

## 取货（减库存）

每行右侧除了「改」「删」，还有一个「取」：

- 点开后在该行下方展开三个输入框：**总数 / 组 / 余**，填任一个另外两个自动同步
- Enter 或点「确认」提交，Esc 或「取消」放弃
- 取到 0 时该行自动删除
- 每次都写流水，记录取出量与约等于几格（`≈2格`），底部「最近操作」里能看到

## 录入数量：一行三格联动

```
数量   [1523]  [组 1]  [余 524]
```

- 三格等高、同一行，和「角色/材料名/位置」对齐
- 填总数 → 自动拆出组和余；只填组和余 → 总数自动算
- 换算结果（`= 1523 个 · 占 2 格`）显示在表单下方单独一行，不撑高输入框
- 存储永远只存总量

## #ID 是什么

材料名右侧的小号 `#5057` 是物品 ID，**只用于图标加载不出来时查图**（点一下可复制）。它不是搜索主键，也不影响任何匹配。


## 排查开关

浏览器打开 `http://127.0.0.1:8765/api/diag` 可以看到：

- 物品表加载了多少条、前几条样例的名称
- 输入「铁锭」能否解析到物品 ID（用来确认 CSV 的名称列没认错）
- 图标已缓存多少个

## 排查

| 现象 | 处理 |
|---|---|
| 双击后窗口一闪而过 | 在文件夹里按住 Shift 右键 → 在此处打开 PowerShell → 跑 `python app.py` 看报错 |
| 提示 Python not found | 装 Python 3.9+，安装时勾选 Add to PATH |
| 页面打不开 | 看窗口里打印的端口号，可能不是 8765（被占用时会自动往后找） |
| 物品表下载失败 | 不影响记账；想补上可手动下载上面的 CSV，另存为 `data\items.json` 是做不到的（格式不同），需要重跑 `python app.py` 让它自动构建 |

## 算料清单（v0.12）

不用记库存也能用：把要做的东西放进清单，程序算给你「要什么材料、自己要做几批、买齐要多少金」。

### 怎么用

1. 打开算料页面（配方测试页），输入成品名，选数量；
2. 点「＋ 添加」继续加，可以加好几样；
3. 支持**粘贴一批**：一行一个，写 `名称 x 数量`（全角 ×、空格、制表符都认）；
4. 点「生成总清单」；
5. 清单会存在浏览器里，**刷新不丢**，下次接着用。

### 同名材料会自动合并

```
两个成品各需要 1 个「高地小麦粉」，每批产 3 个
→ 总需求 2，只做 1 批（不是 2 批）
```

同一材料被多个成品需要时，需求先相加，库存**只扣一次**、批数**只取整一次**。

### 结果分三类

| 分组 | 意思 |
|---|---|
| 待获取 | 还得去搞到的材料（含你指定「直接买」的半成品） |
| 待制作 | 需要自己做的半成品，写明做几批、多做几个 |
| 已备齐 | 库存已经够的部分 |

### 「使用库存」开关

- **开着**：按仓库实际情况扣减，会告诉你「已有 6 个，还差 14 个」；
- **关着**：只算理论需求，纯粹算料。

清空库存、只有配方时，页面会自动进入「算料模式」：只算材料和价格，不显示位置。

### HQ 开关

每个成品可以单独勾「HQ」：

- 勾了：只抵扣仓库里 **HQ** 的那些；
- 没有 HQ 版本的物品（比如大部分材料、药水），勾了也会自动按 NQ 算，不会白跑。

### 价格

- **市场价**：查 Universalis 当前挂单，5 分钟缓存一次；
- **买齐成本**：不是「最低价 × 数量」，而是按挂单**逐档吃**——

  ```
  需要 20 个：46 金 × 1 件 + 60 金 × 12 件 + 75 金 × 7 件 = 1,291 金
  （按最低价 × 20 算只有 920，会低估）
  ```

- **NPC 金币价**：能从 NPC 商店用金币买的物品，会额外给一个单价，直接买的比市场便宜时标出来；
- 价格都是**估算**，不含市场税、不含传送时间、不保证按这个价买齐。

### 买 vs 自制

同一个半成品，先看「直接买要多少」，再看「自己做要多少材料」，两个数字自己比——程序不会替你决定。

## 数据文件说明

| 文件 | 用途 | 大小 |
|---|---|---|
| `data\items.json` | 物品表（名称/图标/堆叠/能否 HQ） | 1.9 MB |
| `data\recipe.json` | 配方索引 | 1.3 MB |
| `data\npc_shop.json` | NPC 金币商店价 | 1.4 MB |

三个都是**缓存**，删了也能重新生成：

```bat
python app.py --build-items     :: 重建物品表
python app.py --build-recipes   :: 重建配方表
python app.py --build-npc       :: 重建 NPC 商店价
```

> 升级版本后如果发现「配方用不了」「NPC 价没有」，多半是这三个文件没更新或没跟着搬过来。
